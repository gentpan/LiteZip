# LiteZip 开发决策

实现参考用户提供的 v0.1 产品开发文档；本文件记录本次实现的实际范围与补充决策。

## 架构

`SwiftUI / AppKit → AppModel（任务队列）→ ArchiveServiceProtocol → ArchiveService → 独立 7zz / zstd 引擎进程`

- macOS 13 为最低目标；Swift 6 严格并发检查；App、扩展、引擎均构建 arm64 / x86_64。
- `LiteZipCore` 只依赖 Foundation 与 Darwin，可由未来 CLI 复用。
- 有阻塞 I/O 的引擎操作放入独立线程，经 continuation 接回 Swift Concurrency，避免阻塞主线程与协作线程池。
- 任务从队列按创建顺序启动，最多两个并行任务，每个压缩引擎默认最多两个工作线程。
- 密码不写入设置、日志、任务持久化或命令行；操作完成后清空任务中的密码引用。
- GUI 使用原生语义颜色与表单、标准面板和系统文件图标，无 WebView 或常驻菜单栏。

## 比原始文档进一步明确的决策

| 问题 | 本次决策 |
| --- | --- |
| 内置引擎和安装依赖 | 7-Zip 官方 universal 独立可替换引擎；ZSTD 独立 universal 工具；无需用户安装其他工具 |
| 压缩成功的判断 | 引擎完成后进行完整性检查与目录安全检查，再发布最终结果 |
| 取消／输出冲突 | 终止正在运行的引擎，必要时强制终止；删除临时结果；`RENAME_EXCL` 防止并发任务覆盖 |
| 临时文件位置 | 放在目标目录同级的私有 `.LiteZip-UUID` 目录，保证同一卷的原子发布；本地日志登记以清理崩溃残留 |
| 特殊路径与链接 | 拒绝 `..`、绝对路径、反斜杠、控制字符、大小写／Unicode 规范化重名、文件目录冲突；拒绝所有链接与特殊文件 |
| 7-Zip 目录解析歧义 | 有歧义就拒绝，不猜测换行文件名或多行注释；实际写入大小不得超过声明大小 |
| 未知展开大小 | 普通压缩流允许未知大小，运行时限额；UI 使用不定进度 |
| ZIP 密码边界 | 7-Zip 26.03 的 ZIP AES 密码要求 ASCII 且不超过 99 字符；提前给出清楚错误，建议切换 7Z |
| Finder 安全默认值 | 始终解压到独立文件夹，不提供“覆盖已有目录”或“删除源文件”快捷菜单 |
| 首版新增功能 | 内容目录、搜索、校验提前到本次基础版，减少不必要的完整解压 |

## 后续优先级

1. 在独立 worker 内集成结构化引擎 API，替代文本目录；在保持路径安全的前提下按一次流解压，改善 Solid 7Z 和大量小文件性能。
2. 实测 10 / 50 / 100 GB、10 万小文件、低磁盘空间、外接盘与 macOS 13 真机；建立内存、取消延迟和启动时间基线。
3. 扩展与主应用间增加 XPC 协议，完善无主窗口的 Finder 快速操作与扩展启用诊断。
4. 完善 metadata、resource fork、extended attributes、权限和时间戳策略；针对允许的链接单独建立安全规则。
5. Apple 公证、Gatekeeper 完整验证、英文和其他语言本地化、通知点击显示结果。
6. 按实际需求增加选择性提取、Quick Look、分卷支持、复用核心的 CLI 和 SHA-256 校验；更新框架等待正式发布与更新源配置后再引入。
7. Mac App Store 另做 Sandbox 版本与 security-scoped bookmarks，不将当前 Developer ID 版本冒充 App Store 就绪。

暂不加入云同步、账号、自动上传、删除源文件或与归档无关的功能。
